# 树莓派终端识别画面说明

本文对应当前版本的树莓派终端页 `/`。

这一版终端页已经刻意做了减法，不再保留大量演示性质的常驻 UI。目标很明确：

- 平时尽量只显示真实摄像头画面
- 识别线程在后台工作
- 只有签到成功时，才在视频流上短暂显示提示

## 1. 页面外层还保留了什么

终端页外层仍然由 [templates/user_screen.html](/home/luck/face3/templates/user_screen.html) 控制，但已经去掉了原来的扫描框和底部等待条。

当前还保留的外层元素主要有：

### 1. 左上角圆点

- 亮色圆点：前端最近一次健康检查判断后端在线。
- 灰暗圆点：前端连续多次探测失败，页面判定后端离线。

### 2. 顶部标题

- `实时识别画面`：后端在线，视频流可用。
- `视频流连接异常，正在重试`：后端在线，但 MJPEG 流暂时断开，前端自动重连。
- `服务连接已断开`：前端连续多次探测 `/healthz` 失败。

### 3. 右侧提示卡片

右侧的“识别提示 / 今日概况 / 现场公告”仍然保留，但它们不参与识别逻辑，只是页面信息展示。

### 4. 左上角小进度提示

当前视频区域左上角保留了一块很小的进度提示卡片。

它只显示三样东西：

- 当前简短状态，例如“等待人脸”“已匹配”“已签到”
- 一句很短的辅助说明
- 一条细进度条

这个提示来自：

- `/api/terminal/status`

设计目标是：

- 给终端前用户一点即时反馈
- 但不再用大块 UI 压住摄像头画面

当前状态提示会优先展示更关键的业务阶段，避免已经进入签到写入或签到冷却时，卡片仍然停留在“已匹配”。

当前优先级是：

- 已签到
- 准备签到
- 冷却中
- 非考勤时段
- 已匹配
- 其他等待或异常状态

## 2. 当前已经移除的 UI

这一版已经从终端页移除这些元素：

- 中间青色扫描取景框
- 扫描线
- “请将面部保持在框内”悬浮提示
- 底部等待识别状态条
- 视频流左上角常驻调试 HUD
- 实时人脸框颜色调试层

这样做的原因是：

- 会遮挡真实摄像头画面
- 对签到成功本身帮助不大
- 容易让终端页显得过于嘈杂

## 3. 视频流里现在会出现什么

### 1. 正常待机时

默认只显示摄像头原始画面，不再叠加识别状态文字。

### 2. 签到成功时

视频流底部会短暂出现一条成功提示：

- 标题：`签到成功`
- 内容：`姓名 编号 签到成功`

这是当前终端页唯一保留的实时业务提示。

### 3. 摄像头异常时

如果摄像头打不开或连续读帧失败，会显示占位页，例如：

- `摄像头正在启动`
- `当前无法打开摄像头`
- `摄像头读取失败`

并且附带一条排查提示：

- `请检查摄像头编号配置或访问权限`

## 4. 识别逻辑说明

虽然终端页上不再显示那些调试框和调试字，但后台识别仍然在运行。

当前主流程是：

1. 检测当前画面中是否只有一张脸
2. 脸太小则继续等待
3. 直接提取当前脸的人脸编码
4. 与本地已注册人脸库做距离比对
5. 如果最优匹配足够近，就直接通过
6. 通过后写入考勤并保存快照

当前版本已经不再把这些条件作为硬门槛：

- 画面模糊
- 亮度偏暗或偏亮
- 明显歪头
- 左右侧脸角度
- 抬头或低头姿态

保留的核心约束只有：

- 单人入镜
- 脸别太小
- 编码匹配要足够接近
- 冷却时间避免重复签到
- 必须处于考勤时间段

## 5. 当前关键参数

当前默认参数已经调成更偏向“快速签到”的版本：

- `face_distance_threshold = 0.52`
- `face_match_required_times = 1`
- `recognition_target_fps = 5`
- `min_face_area_ratio = 0.03`

这意味着：

- 识别会更快放行
- 不需要连续很多帧稳定
- 对距离摄像头的要求没之前那么苛刻

## 6. 中文字体显示说明

当前视频流内的中文绘制使用的是 [scripts/camera/frame_text.py](/home/luck/face3/scripts/camera/frame_text.py)。

字体查找顺序是：

1. `env.json` 中的 `camera_overlay_font_path`
2. 项目 `static/fonts/` 下的字体
3. 树莓派系统自带的中文字体，例如：
   - `wqy-zenhei`
   - `wqy-microhei`
   - `Noto Sans CJK`
   - `DroidSansFallbackFull`

如果系统里存在这些字体，终端页里的中文就不应该再显示成 `????`。
